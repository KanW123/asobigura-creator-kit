# 安全性と確認範囲

- CLIは利用者と同じOS権限で動きます。Node.jsを入れたから安全になるわけではありません。公式案内の配布元、バージョン、SHA256を確認してください。
- 認証は外部ブラウザ＋PKCE、127.0.0.1の一時ポートで受信します。試行照合とHost/Originを検証し、3分で終了。検証済みセッションのみ保存します。共有設定を変更せずMacで実認証を確認しました。
- 認証保存先は専用ホームディレクトリ。POSIXは0700/0600、Windowsは本人のみにACLを設定・再検証。管理者権限や同一ユーザーの悪意あるプログラムから守る暗号化保管庫ではありません。
- ZIP展開は専用プロセス、15秒の期限、サイズ・件数・パス検査を使用。異常終了時は投稿前に停止します。任意のファイルを実行するサンドボックスではありません。第三者から受け取った不明なゲームを無条件で実行しないでください。
- 配布ZIPは許可したファイルだけで組み立て、依存のライセンス、ファイル一覧とハッシュを同梱します。認証ファイル、内部記録、サーバ側の鍵は含めません。Supabaseのpublishable keyは公開クライアント用です。
- SHA256はファイル一致の検証で、配布元のなりすましを単独で防ぐものではありません。公開リリースではActionsのattestationも検証します。これは来歴の証明であり、ソフトの無欠陥を保証するものではありません。

来歴確認（GitHub CLIを使う場合。普段の利用には不要）:

```sh
gh attestation verify <取得したZIP> --repo <公式の所有者/リポジトリ>
```

問題の報告ではトークン・パスワード・credentials.jsonを添付しないでください。公開前のプロジェクト情報を含む報告は公開Issueへ書かず、公式サイトの問い合わせ先へ連絡してください。

参照: [GitHub artifact attestations](https://docs.github.com/en/actions/concepts/security/artifact-attestations)、[OAuth RFC8252](https://www.rfc-editor.org/rfc/rfc8252)。
